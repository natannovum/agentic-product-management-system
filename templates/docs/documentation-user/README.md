# End-User Documentation

Source for what users read to operate the product: setup, per-feature guides, troubleshooting, and — where the product requests permissions or collects data — a plain explanation of what and why.

**Updated whenever user-visible behaviour changes.** This obligation is checked at pull-request time, not remembered later (`CLAUDE.md` → Git workflow, rule 5).

**If the manual is published as part of the marketing site**, keep it under `product-marketing/user-manual/` instead and delete this directory — one source of truth per surface, not two.

**Attribute correctly.** Where behaviour comes from an underlying platform or framework rather than from this product, say so. Readers troubleshoot in the wrong place otherwise, and the distinction is invisible from the outside.
